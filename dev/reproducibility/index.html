Reproducibility

The vignettes in docs/src/vignettes/ reproduce the analyses of the manuscript Discrete dynamic survival analysis of epidemic case line lists. This page explains how to rerun them and how the results compare with the manuscript's published results.

Rerunning the manuscript analyses

Manuscript AnalysisVignette
What each likelihood term contributes (synthetic outbreak)data availability

With the environment variable DDSA_FULL=true, the vignettes use the manuscript's settings:

  • 4 chains of 2,000 draws after 1,000 NUTS adaptation steps, with 4,000 draws for the scenario B NegBin and Boxcar fits of the data-availability example;
  • in the DDSA-vs-ODE comparison, 2,000 adaptation steps for the ODE count models, with target acceptance 0.95 (0.8 for the $\gamma$-fixed model).

The pages in this documentation were rendered with these settings and are shown without being rerun. Without DDSA_FULL=true the scripts use fewer chains and draws (as few as 2 chains of 100 draws) with shorter adaptation, and the Ebola vignette fits only wave 2. That mode only checks that the code works, and its estimates do not replicate the manuscript's results.

julia --project=docs -e 'using Pkg; Pkg.instantiate()'
julia --project=docs --threads=10 docs/render_vignettes.jl              # re-render the pages, ≈15 min
julia --project=docs --threads=10 scripts/reproduce_manuscript.jl       # rerun and compare, ≈15 min
julia --project=docs --threads=10 scripts/reproduce_manuscript.jl h1n1_wsu ebola_drc
DDSA_FULL=true julia --project=docs --threads=10 docs/src/vignettes/h1n1_wsu.jl   # one vignette

Each vignette sets the manuscript's priors, $r$ support, $K_\text{age}$, NUTS settings and numerical guards.

The two Boxcar analyses truncate the infectious period $W$ at $K_\text{age}$ age classes in different ways:

  • Data availability: the hazard of $W$ conditioned on $W \le K_\text{age}$, which is truncation = :condition in discrete_hazard;
  • Hagelloch: the exact hazard of $\min(W, K_\text{age})$, which is truncation = :absorb.

Other notes:

  • Data: the synthetic data set of the data-availability and DDSA-vs-ODE examples is regenerated: simulate_linelist(Xoshiro(1234), dph_erlang_from_mean(4, 4.0, 1.0), 0.5, 0.01, 99, 40) gives the same 91 cases, infection histogram and intervals.
  • Predictive checks: posterior_predictive and recovery_predictive use draws that are evenly spaced across all combined chains.

Comparison with the manuscript

scripts/reproduce_manuscript.jl runs each vignette with the full settings. It compares the posterior medians and 95% limits with the manuscript's posterior tables (test/reference/manuscript_posteriors.toml). A quantity passes if one of two rules holds:

  • Posterior SD: measured in the posterior sd of the new run, its median is within 0.1 sd and its limits within 0.2 sd.
  • Monte Carlo error: a median or limit outside that tolerance still passes if it is within 2 combined Monte Carlo standard errors. The combined error is $\sqrt{2} \times \mathrm{MCSE}$ of the new run's estimate (MCMCDiagnosticTools.mcse). The script reports these quantities as "pass (MCSE)".

Agreement is within Monte Carlo error.

Regression tests

The regression fixtures come from the Quarto-notebook implementation of the analyses, at commit 8ea70c9 of epirecipes/DDSA. test/reference/generate_reference.jl ran that implementation and saved its outputs in test/reference/*.toml. The tests compare the package against them:

The package builds $\tau$ and $f$ from the new infections recorded at each step. Where new infections are tiny ($R_0 < 1$), this is more precise than differences of the susceptible fraction, which explains the small differences in f. A few phase-type functions also differ from the notebook implementation at edge cases. For example negbin_total_logpdf at $p = 1$, and pmf and cdf for $n < 1$.

Environments

  • Package: Project.toml declares compatibility bounds only. The tested versions differ slightly from those used for the manuscript: Distributions 0.25.132 (manuscript 0.25.131), StatsFuns 2.2.1 (1.5.3), MCMCChains 7.8.1 (7.7.0). Turing is 0.49.0 in both.
  • Documentation and vignettes: docs/Project.toml. Plots, StatsPlots and OrdinaryDiffEq resolve to the versions used for the manuscript.
  • Julia: ≥ 1.11. Tested with 1.11.6, the version used for the manuscript.
